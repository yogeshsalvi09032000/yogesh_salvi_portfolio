Project Overview

Developed a wearable haptic glove system designed to reduce hand tremors in Parkinson's disease patients through precisely timed vibrotactile cues. The system uses Variable Frequency Complex Repetitive (VCR) stimulation patterns delivered through Linear Resonant Actuators (LRAs) positioned on each finger, achieving synchronized bilateral stimulation across both hands via wireless ESP-NOW communication.

Key Features

  • Bilateral Haptic Stimulation: Synchronized 4-motor arrays on both hands (8 motors total)
  • VCR Pattern Generation: Variable frequency complex repetitive stimulation patterns using 24 permutations
  • Wireless Synchronization: ESP-NOW protocol for sub-20ms latency between master and slave gloves
  • Web Bluetooth Control: Progressive Web App (PWA) for wireless parameter tuning via smartphone
  • Persistent Settings: NVS (Non-Volatile Storage) for parameter retention across power cycles
  • 3D Printed Enclosures: Custom finger-mounted housings for LRA motors
  • Dual ESP32 Architecture: Separate microcontrollers for master (left) and slave (right) hands
  • DRV2605 Motor Drivers: Professional haptic driver ICs with waveform library

System Architecture

Hardware Components

  • Microcontrollers: 2× ESP32 DevKit (Master: 00:4B:12:3B:73:3C, Slave: 00:4B:12:3A:A9:94)
  • Haptic Drivers: 8× Adafruit DRV2605L Haptic Motor Controllers
  • Motors: 8× Linear Resonant Actuators (LRA) - precision vibration motors
  • I2C Multiplexer: 2× TCA9548A (1×8 I2C multiplexer) for addressing 4 DRV2605 per hand
  • Enclosures: 8× Custom 3D-printed finger mounts
  • Power: Dual battery system (one per glove) for independent operation

Communication Architecture

The system employs a master-slave wireless architecture:

  • Master Glove (Left Hand): Pure ESP-NOW operation, reads settings from NVS, generates VCR patterns, broadcasts sync packets to slave
  • Slave Glove (Right Hand): Dual-radio operation - BLE for smartphone control, ESP-NOW for receiving master sync, writes settings to shared NVS
  • ESP-NOW Protocol: <20ms latency, reliable packet delivery, no WiFi infrastructure required
  • BLE GATT Server: Custom service (UUID: 4fafc201-1fb5-459e-8fcc-c5c9c331914b) with 3 characteristics for MA, PD, BD parameters

Technical Implementation

VCR Stimulation Pattern

The Variable Frequency Complex Repetitive (VCR) pattern is designed to disrupt tremor oscillations through carefully timed haptic cues:

  • Pattern Structure: 3 sequential periods, each activating all 4 motors in randomized order
  • Permutation Table: 24 possible motor firing orders to prevent habituation
  • Burst Duration (BD): 50-150ms per motor activation (default: 100ms)
  • Pattern Duration (PD): 500-1000ms total cycle time (default: 744ms)
  • Motor Amplitude (MA): 50-100% intensity mapped to DRV2605 effects 1-14
  • Quiet Period: 2× PD between pattern cycles to allow neural reset

I2C Multiplexing Strategy

Since DRV2605 drivers have fixed I2C addresses, TCA9548A multiplexers enable 4 drivers per ESP32:

  • Each DRV2605 connects to a dedicated TCA9548A channel (0-3)
  • Software selects active channel before each motor command
  • Prevents address conflicts while maintaining independent motor control
  • 5ms settling delay after channel switching ensures reliable communication

Firmware Architecture

Master Glove (GloveMaster.ino)

  • Pure ESP-NOW operation (no BLE to avoid radio conflicts)
  • Loads settings from NVS written by slave glove
  • Generates random VCR patterns using 24-permutation table
  • Broadcasts GloveSync packet to slave before each pattern
  • Executes synchronized motor firing sequence
  • Operates in continuous loop with 2×PD quiet periods

Slave Glove (GloveSlave.ino)

  • Dual-radio operation: BLE + ESP-NOW
  • BLE GATT server exposes 3 characteristics (MA, PD, BD)
  • Writes received BLE parameters to NVS (shared with master)
  • ESP-NOW receiver waits for master sync packets
  • Executes identical VCR pattern synchronized to master
  • Callbacks ensure atomic parameter updates

Challenges & Solutions

Challenge: BLE and ESP-NOW Compilation Conflicts

Problem: Initial attempts to run both BLE GATT server and ESP-NOW receiver on the same ESP32 resulted in compilation errors with conflicting WiFi radio states and library header clashes. The ESP32's single 2.4GHz radio must be carefully managed when using multiple wireless protocols.

Solution: Implemented asymmetric architecture - master glove runs pure ESP-NOW (WiFi STA mode only), while slave glove handles all BLE communication (peripheral mode). Both protocols can coexist on the slave ESP32 because BLE peripheral and ESP-NOW use different radio timeslots. Thoroughly tested radio coexistence with packet loss monitoring to ensure <1% failure rate.

Challenge: Library Version Incompatibilities

Problem: ESP32 Arduino core updates broke existing Adafruit_DRV2605 library calls, causing undefined reference errors during linking. The I2C Wire library API changed between core versions 1.0.6 and 2.0.x, requiring different initialization sequences.

Solution: Pinned ESP32 Arduino core to version 2.0.11 in platformio.ini and updated Wire.begin() calls to explicitly specify SDA/SCL pins (21, 22). Added verbose compiler flags to catch deprecated API usage early. Documented exact library versions in project README for reproducibility.

Challenge: I2C Address Conflicts with Multiple DRV2605

Problem: DRV2605 haptic drivers have a fixed I2C address (0x5A), making it impossible to connect more than one directly to the ESP32's I2C bus. Initial attempts with software I2C proved unreliable at motor control speeds.

Solution: Implemented TCA9548A I2C multiplexer topology. Each motor driver connects to a dedicated multiplexer channel, selected via software before each command. Added 5ms settling delay after channel switching to ensure reliable communication. This scales to 8 motors per multiplexer (only using 4 per hand).

Challenge: Bilateral Synchronization Latency

Problem: Initial BLE-based synchronization between gloves exhibited 100-200ms latency due to GATT notification overhead, connection interval constraints, and packet queuing. This caused visible motor firing delays between hands, reducing therapeutic effectiveness.

Solution: Switched to ESP-NOW protocol for inter-glove communication. ESP-NOW achieves <20ms latency through direct MAC-layer packets without connection overhead. Master sends sync packet with pattern permutations and timing parameters before firing, ensuring both gloves start within one motor burst duration. Verified synchronization with oscilloscope measurements.

Challenge: Parameter Persistence Without Re-Pairing

Problem: Settings adjusted via BLE app were lost on power cycle. Real-time BLE broadcasts from slave to master proved unreliable during active motor patterns due to radio contention and packet collisions.

Solution: Implemented shared NVS (Non-Volatile Storage) namespace between master and slave. Slave writes BLE-received parameters to flash memory; master reads from same namespace on each loop iteration. Settings survive power cycles without requiring active BLE connection. NVS wear leveling ensures 100,000+ write cycles before flash degradation.

Challenge: Motor Habituation to Repetitive Patterns

Problem: Fixed motor firing sequences led to neural habituation - patients' tremor reduction decreased after 15-20 minutes of use as the nervous system adapted to predictable stimulation patterns.

Solution: Implemented 24-permutation lookup table for randomized motor firing sequences. Each VCR cycle uses 3 randomly selected permutations, creating 13,824 possible pattern combinations. Added pseudo-random seed based on analogRead() to ensure different patterns across power cycles. Quiet periods (2× pattern duration) between cycles prevent continuous habituation.

Challenge: Debugging Multi-Device Wireless Systems

Problem: Traditional Serial debugging only shows one ESP32 at a time. Synchronization issues between master and slave were difficult to diagnose without seeing both devices' states simultaneously.

Solution: Implemented verbose logging with timestamp prefixes and device identifiers. Used dual USB connections to monitor both gloves in separate terminal windows. Added ESP-NOW callback debugging to log packet send/receive events. Integrated LED feedback (built-in LED flashes during pattern execution) for visual confirmation of motor timing without serial connection.

Key Learnings

This project provided hands-on experience with complex embedded systems integrating multiple wireless protocols, haptic feedback hardware, and real-time synchronization constraints. Learned the importance of radio coexistence strategies when combining BLE and ESP-NOW on the same hardware. Discovered that I2C multiplexing is essential for scaling beyond 2-3 identical address devices. The shared NVS approach proved more reliable than real-time BLE parameter broadcasts for maintaining consistent settings across distributed systems.

Future Enhancements & Next Steps

This prototype demonstrates the core haptic stimulation concept. The next phase focuses on making the system more intelligent, wearable, and clinically testable:

Near-Term Improvements (3-6 months)

  • IMU Integration (MPU6050): Add 3-axis accelerometer to measure actual tremor amplitude before and after stimulation - quantify efficacy rather than relying on subjective feedback
  • Battery Monitoring: Integrate fuel gauge IC and implement low-power sleep modes to achieve 6-8 hour continuous operation between charges
  • Data Logging: Add microSD card module to record tremor measurements, stimulation parameters used, and timestamps - essential for clinical validation
  • Improved Enclosures: Redesign 3D-printed housings with ergonomic finger contours and ventilation slots for extended wear comfort

Medium-Term Development (6-12 months)

  • Adaptive Pattern Selection: Use recorded IMU data to identify which VCR patterns work best for individual users - simple statistical analysis to auto-select effective permutations
  • iOS App Development: Build native Core Bluetooth app for iPhone users with offline data sync and treatment session history tracking
  • Textile Integration: Partner with wearable tech designers to embed motors and electronics into washable glove substrate - move from prototype to daily-wearable device
  • Clinical Pilot Study: Work with local neurology clinic to conduct IRB-approved usability testing with 5-10 Parkinson's patients - gather real-world feedback on comfort, efficacy, and usability

Long-Term Vision (1-2 years)

  • Closed-Loop Control: Implement real-time tremor frequency detection from IMU to automatically adjust stimulation timing - match haptic cues to actual tremor oscillations instead of fixed patterns
  • Multi-Site Comparison: Design wrist-band and forearm-band variants to test whether proximal stimulation is more effective than finger-mounted motors
  • Open-Source Release: Publish complete hardware designs, firmware, and web app to GitHub - enable researchers and makers worldwide to replicate and improve the system

The Next Chapter

What excites me most? The IMU integration. Right now, we're delivering stimulation blindly - we don't actually know if the tremor is reducing. Adding an accelerometer transforms this from a "haptic glove" into a "tremor measurement and intervention system."

The MPU6050 costs $3, uses the same I2C bus we're already running, and can sample at 100Hz - more than fast enough to capture 4-12Hz Parkinsonian tremor. The firmware changes are straightforward: read accelerometer data, run FFT to extract tremor frequency, log amplitude before/during/after stimulation.

That's V2. Same glove, smarter brain, measurable results. The hardware's ready. The math is known. Now it's just a matter of building it.

Medical Context & Motivation

Parkinson's disease affects over 10 million people worldwide, with tremor being one of the most visible and debilitating symptoms. Vibrotactile cueing has shown promise in clinical studies as a non-invasive method to reduce tremor amplitude by disrupting the pathological neural oscillations driving the tremor. This glove system implements VCR (Variable Frequency Complex Repetitive) stimulation patterns based on research suggesting that varied, complex haptic feedback is more effective than simple repetitive pulses.
