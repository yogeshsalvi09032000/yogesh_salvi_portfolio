Line Follower Robot
Real-Time Embedded Control

Model-Based Design with Simulink and Arduino Deployment

Project Overview

This project implemented a real-time embedded control system for an autonomous line-following robot using model-based design methodology. The system was developed entirely in MATLAB Simulink and deployed directly to Arduino hardware, demonstrating rapid prototyping and hardware-in-the-loop testing capabilities.

Project Demo


Project Objectives

  • Design complete control system using Simulink block diagrams
  • Implement differential drive control for line tracking
  • Deploy real-time code to Arduino microcontroller
  • Achieve robust line following on curved and straight paths
  • Collect and analyze motor speed data using encoder feedback
  • Validate system performance through experimentation

System Architecture

The line follower robot consisted of three main subsystems:

1. Sensing Subsystem

  • IR Reflective Sensors: Array of 5 infrared sensors detecting line position
  • Sensor Configuration: Evenly spaced across robot width for coverage
  • Digital Output: Binary signal (HIGH = line detected, LOW = no line)
  • Threshold Tuning: Calibrated for different surface reflectivities

2. Control Subsystem

  • Threshold-Based Logic: Simple yet effective decision-making
  • Differential Drive Control: Independent left/right motor speed commands
  • PWM Output: Pulse-width modulation for motor speed control
  • Direction Control: Fixed direction pins for forward motion

3. Actuation Subsystem

  • DC Gear Motors: Two motors providing differential drive
  • Motor Driver: L298N H-bridge for bi-directional control
  • Wheel Encoders: Optical encoders for speed measurement
  • Power Supply: 7.4V Li-Po battery with voltage regulation

Simulink Model Design

The entire control system was modeled using Simulink block diagrams, enabling:

  • Visual programming without writing embedded C code
  • Simulation and testing before hardware deployment
  • Automatic code generation for Arduino
  • Real-time monitoring of internal signals
  • Easy parameter tuning through Simulink interface

Model Structure

The Simulink model contained the following key blocks:

  • Digital Input: Read IR sensor values (5 digital pins)
  • Logic Blocks: Implement line-following decision logic
  • PWM Output: Generate motor speed commands (0-255)
  • Digital Output: Control motor direction (forward/backward)
  • Encoder Input: Read wheel speed from optical encoders
  • Display/Scope: Monitor sensor and motor signals in real-time

Control Algorithm

The line-following algorithm used threshold-based logic to determine steering commands:

Sensor Configuration

Sensor Array:  [S1] [S2] [S3] [S4] [S5]
Position:       Far  Mid  Center Mid  Far
               Left Left       Right Right

Control Logic

Sensor Reading Robot Position Left Motor Right Motor Action
00100 Center (on line) HIGH HIGH Forward
01000 Slightly left MEDIUM HIGH Slight right
10000 Far left LOW HIGH Sharp right
00010 Slightly right HIGH MEDIUM Slight left
00001 Far right HIGH LOW Sharp left

PWM Speed Control

Motor speeds were controlled using PWM (Pulse Width Modulation):

  • HIGH speed: PWM = 200 (78% duty cycle)
  • MEDIUM speed: PWM = 150 (59% duty cycle)
  • LOW speed: PWM = 100 (39% duty cycle)
  • STOP: PWM = 0 (0% duty cycle)

Hardware Deployment

The Simulink model was deployed to Arduino hardware using the Simulink Support Package for Arduino:

Deployment Process

  1. Model Development: Build and test control logic in Simulink
  2. Simulation: Validate behavior using software-in-the-loop testing
  3. Code Generation: Automatically generate embedded C code
  4. Compilation: Compile code for Arduino Uno target
  5. Upload: Flash compiled binary to Arduino via USB
  6. Execution: Real-time execution on hardware at fixed time step

Real-Time Execution

  • Sample Time: 10 ms (100 Hz control loop)
  • Deterministic Timing: Fixed-step solver ensures consistent timing
  • Overrun Protection: Error detection if execution exceeds sample time

Data Acquisition & Analysis

Wheel encoders provided real-time speed feedback for performance evaluation:

Encoder Configuration

  • Type: Optical rotary encoders (slotted disk + IR sensor)
  • Resolution: 20 pulses per revolution
  • Sampling: Interrupt-driven pulse counting
  • Processing: Convert pulse count to RPM

Speed Calculation

Motor speed was calculated from encoder pulses: 

RPM = (Pulses / PPR) × (60 / Δt)

Where:
- Pulses = Encoder counts in time interval
- PPR = Pulses Per Revolution (20)
- Δt = Time interval in seconds (0.1s for 10 Hz logging)

Data Logging

The following data was logged during test runs:

  • Left motor PWM command (0-255)
  • Right motor PWM command (0-255)
  • Left wheel speed (RPM)
  • Right wheel speed (RPM)
  • Sensor array readings (binary)
  • Timestamp (milliseconds)

Results & Performance

The line follower robot successfully tracked various line configurations:

Test Scenarios

  • Straight Line: Stable tracking with minimal oscillation
  • Gentle Curves: Smooth cornering without line loss
  • Sharp Turns (90°): Successfully navigated with correct differential drive
  • Intersections: Continued straight when configured
  • Gaps: Brief line gaps handled by momentum

Performance Metrics

  • Average Speed: ~15 cm/s on straight sections
  • Success Rate: 95% completion on test track (20 laps)
  • Line Loss Events: Average 0.5 per lap (recovered automatically)
  • Control Loop Frequency: Stable 100 Hz execution
  • Response Time: <100ms from sensor input to motor adjustment

Challenges & Solutions

Challenge: Sensor Noise and Ambient Lighting

Solution: Implemented digital filtering in Simulink using moving average. Added physical shielding around IR sensors to reduce ambient light interference. Calibrated thresholds for specific lighting conditions.

Challenge: Overshoot on Sharp Turns

Solution: Tuned differential drive ratios to provide more aggressive steering. Reduced overall speed approaching turns. Added anticipatory logic based on sensor pattern recognition.

Challenge: Encoder Signal Bouncing

Solution: Implemented interrupt-driven counting with debouncing delay (5ms). Used hardware pull-up resistors on encoder inputs. Added software filtering to reject spurious pulses.

Challenge: Battery Voltage Drop

Solution: Implemented voltage compensation by monitoring battery level and increasing PWM values proportionally as voltage dropped. Added low-voltage cutoff protection.

Key Learnings

This project demonstrated the power of model-based design for embedded systems development. The visual programming approach in Simulink enabled rapid prototyping and intuitive system visualization. Learned the importance of sensor calibration, the effectiveness of simple threshold-based control for constrained environments, and the value of real-time data acquisition for system validation. The project reinforced understanding of PWM control, differential drive kinematics, and embedded system constraints.
