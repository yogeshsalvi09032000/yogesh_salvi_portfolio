ML-Based Bone Fracture
Classification from X-Rays

Convolutional Neural Network for Medical Image Analysis

Project Overview

Developed a deep learning system to automatically classify bone fractures from X-ray images. The project implemented a convolutional neural network (CNN) achieving 94.7% accuracy in distinguishing between simple and comminuted fractures. The complete machine learning pipeline included data preprocessing, model training, evaluation, and real-time inference deployment.

Project Demo


Problem Statement

Bone fracture diagnosis requires expert radiologist interpretation, which can be time-consuming and subject to human error. Automated classification systems can assist medical professionals by:

  • Providing rapid preliminary screening of X-ray images
  • Reducing diagnostic workload in emergency departments
  • Ensuring consistent analysis across different medical facilities
  • Flagging complex fractures requiring specialist attention
  • Supporting educational training for medical students

Project Objectives

  • Build CNN model to classify fracture types (simple vs. comminuted)
  • Achieve >90% classification accuracy on test set
  • Implement complete ML pipeline from data to deployment
  • Optimize for real-time inference (<1 second per image)
  • Create robust model that generalizes to unseen X-rays

Dataset: MURA (Musculoskeletal Radiographs)

The project used a subset of the MURA dataset, a large-scale collection of musculoskeletal X-ray images from Stanford ML Group:

  • Total Images: 16,000+ bone radiographs
  • Classes: Simple fractures vs. Comminuted fractures
  • Image Format: Grayscale PNG (various resolutions)
  • Data Split: 70% training, 15% validation, 15% test
  • Class Balance: Addressed through data augmentation

Data Preprocessing Pipeline

Raw X-ray images underwent multi-stage preprocessing to improve model performance:

1. Contrast Enhancement (CLAHE)

Applied Contrast Limited Adaptive Histogram Equalization to improve visibility of fracture lines:

  • Divided image into 8×8 tiles
  • Applied histogram equalization per tile
  • Limited contrast amplification to prevent noise amplification
  • Bilinear interpolation to eliminate tile boundaries

2. Image Resizing

Standardized all images to 128×128 pixels:

  • Reduced computational cost while preserving fracture features
  • Maintained aspect ratio during resize
  • Applied anti-aliasing to prevent artifacts

3. Normalization

Pixel intensity normalization for stable training: 

normalized_pixel = (pixel - mean) / std
Where mean = 0.5, std = 0.5 (maps to [-1, 1] range)

4. Data Augmentation

Generated additional training samples to improve generalization:

  • Rotation: ±15 degrees (simulates different patient positioning)
  • Zoom: 0.9 to 1.1× (handles different X-ray magnifications)
  • Horizontal Flip: 50% probability (left/right symmetry)
  • Brightness Adjustment: ±10% (simulates different X-ray exposure)

CNN Architecture

Designed a lightweight convolutional neural network optimized for medical image classification:

Network Structure

Input Layer: 128×128×1 (grayscale image)
    ↓
Conv Block 1: 32 filters, 3×3 kernel, ReLU activation
MaxPool: 2×2
    ↓
Conv Block 2: 64 filters, 3×3 kernel, ReLU activation
MaxPool: 2×2
    ↓
Conv Block 3: 128 filters, 3×3 kernel, ReLU activation
MaxPool: 2×2
    ↓
Flatten Layer
    ↓
Dense Layer: 256 neurons, ReLU, Dropout (0.5)
    ↓
Output Layer: 2 neurons, Softmax (Simple vs. Comminuted)

Total Parameters: ~790,000

Key Design Choices

  • ReLU Activation: Faster training, prevents vanishing gradients
  • MaxPooling: Spatial downsampling, translation invariance
  • Dropout (50%): Regularization to prevent overfitting
  • Batch Normalization: Stabilizes training, allows higher learning rates

Training Process

Hyperparameters

  • Optimizer: Adam (adaptive learning rate)
  • Initial Learning Rate: 0.001
  • Batch Size: 32 images
  • Epochs: 50 (with early stopping)
  • Loss Function: Categorical Cross-Entropy

Learning Rate Scheduling

Implemented ReduceLROnPlateau to improve convergence:

  • Monitor validation loss every epoch
  • If no improvement for 5 epochs → reduce LR by factor of 0.5
  • Minimum learning rate: 1e-6
  • Allows fine-tuning in later training stages

Early Stopping

Prevented overfitting by monitoring validation performance:

  • Patience: 10 epochs without validation improvement
  • Restore best model weights before stopping
  • Saved computational resources

Real-Time Inference System

Deployed the model for real-time X-ray classification:

Inference Pipeline

  1. Load unseen X-ray image (any resolution)
  2. Apply CLAHE preprocessing
  3. Resize to 128×128 pixels
  4. Normalize pixel values
  5. Forward pass through CNN
  6. Softmax output → classification probability
  7. Display result with confidence score

Performance Metrics

  • Inference Time (CPU): ~0.18 seconds per image
  • Inference Time (GPU): ~0.04 seconds per image
  • Model Size: 9.5 MB (compressed)
  • Memory Usage: <200 MB RAM

Deployment Options

  • Python script for batch processing
  • Flask web application for browser-based inference
  • TensorFlow Lite for mobile deployment
  • ONNX export for cross-platform compatibility

Challenges & Solutions

Challenge: Class Imbalance in Dataset

Solution: Applied data augmentation more aggressively to minority class. Used class weights during training to penalize misclassification of rare class. Achieved balanced precision/recall across both classes.

Challenge: Overfitting on Training Data

Solution: Implemented dropout (50%) in dense layers. Added L2 regularization to convolutional layers. Used early stopping based on validation loss. Increased training data through augmentation.

Challenge: Variable Image Quality

Solution: CLAHE preprocessing standardized contrast across different X-ray machines and exposure settings. Data augmentation simulated various imaging conditions. Robust normalization handled brightness variations.

Challenge: Computational Constraints

Solution: Downsized images to 128×128 (instead of 256×256) without significant accuracy loss. Used lightweight CNN architecture. Optimized batch size for available GPU memory. Achieved <1 second inference on CPU.
